# Native internationalization

Shared module 1.1.1, independently authored under MIT. Read [the locale registry](locales.json), [the local runtime](../src/i18n.js) and [catalog validator](../scripts/validate-i18n.mjs) before adding UI text. All necessary sources are copied into this repository; no parent checkout is needed. Read [the reuse license](../src/licenses/extension-i18n.txt).

The browser UI language selects en or fr automatically. English is the native fallback. Only English and French catalogs are maintained; no additional translation drafts are retained. The active consumer registry deliberately limits shared module 1.1.1 to English and French; adding languages requires a new explicit user decision. No manual selector, stored locale, network translation or new permission is used.

Keep English source messages with stable semantic keys, translator descriptions and named placeholders. Add complete translations to every supported catalog. Use textContent and the helper's restricted attribute renderer; mark text-only leaves with data-i18n. Translate entire dynamic messages and format numbers with Intl; never localize persisted data.

In extension documents, set locale/direction on the document element. For injected UI, set them only on the extension-owned shadow host; never change the visited page's language/direction. Keep trust checks and closed shadow roots intact. Use logical CSS and wrap long translated labels.

Run the complete check/test/build commands. Validate all catalog references and packaging, test each native browser locale plus unsupported fallback and pt-PT, and distinguish disposable Chromium acceptance from personal Chrome verification. The macOS test launcher uses process-only Cocoa language arguments; it never changes system or user preferences.
